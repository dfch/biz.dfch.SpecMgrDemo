# contracts

The interface contracts. The project writes the OpenAPI file first. The generators make the code from it (DEC f92e35a1-77a2-4749-917f-bf9b644e8ddd).

| File | Content |
|---|---|
| `openapi.yaml` | The only source for the interfaces between the backend and the frontend (OpenAPI 3.1.0). It has one example operation: `GET /status` |

The pipeline of `feat-6-contracts-openapi-pipeline` has these recipes. The recipe `lint` examines the file (the linter is Spectral). The recipe `breaking-changes` finds the breaking changes (the tool is oasdiff). The recipe `generate` makes the generated code (the generators are the plug-in and Kubb). The recipe `api-docs` makes the API documentation. The recipe `check-generated` compares the generated code with the code that the generators make at this time. The recipe `compile` starts the build of the Maven module and the build of the pnpm module. CI has a job with the same name as each of these recipes. The five jobs `lint`, `breaking-changes`, `check-generated`, `compile` and `api-docs` are required checks in the rulesets of `dev` and `main` (since 2026-11-07). See `branch-protection.md` in the folder of feat-5.

## A change of an interface starts in the OpenAPI file

Start a change of an interface in `contracts/openapi.yaml`, and not in the backend or in the frontend. After the change, make the code again with `just generate`. A change that removes or changes something that a client uses is a breaking change. The project accepts the change only with a higher `info.version`. The change has an entry in an ignore file in `tools/`. The owner examines each entry (DEC 93594b2b-be54-4f60-9f53-ec2ce6c84be4).

## Generated code

The generators make this code from the OpenAPI file. The two folders are committed to git. The gate `check-generated` can compare them with the code that the generators make at this time:

| Folder | Content | Generator |
|---|---|---|
| `backend/src/generated` | The Spring server interfaces (Java) | `openapi-generator` 7.27.0, generator `spring` |
| `frontend/src/generated` | The Zod schemas (TypeScript), with the list of error codes | Kubb |

Make the code again with `just generate`. The recipe deletes the two folders, starts the generators and writes the marks. Two starts one after the other give the same files. The files have no time value, no value that changes and no path of the machine (REQ-011). Each folder has a `README.md` with the mark `Generated code, do not change`. Each Java file has `@Generated`. Each TypeScript file starts with the text that Kubb writes at the start of the file. The text is `Generated by Kubb (https://kubb.dev/). Do not edit manually.` No person changes a file of the generated code by hand.

The gate for generated code (`just check-generated`, the CI job `check-generated`) makes the code again. The gate stops the pull request if the result is not the same as the code of HEAD. The gate finds a file that is changed, deleted, not in the index of git or ignored by git. It finds a file that the folder should not have. It finds a missing mark. Change the OpenAPI file, make the code again, and commit the result. On your machine, commit the generated code before you start `just check-generated`. The gate stops for a change in the generated folders that is not committed. The gate does not replace a change by hand.

```bash
just generate   # makes the generated code again
just check-generated   # makes the code again and compares it with HEAD (commit the generated code first)
just compile    # compiles the Maven module and the pnpm module with the generated code
just api-docs   # makes the HTML documentation in build/api-docs (not in git)
```

The test of the generators is the recipe `just test-generate-gate`. The test has two starts of `just generate`, and the two starts give no change. The test has the list of error codes (`components.schemas.ErrorCode`). The list is the same in this file, in the Java enum `ErrorCode` (the test compares by `getValue()`) and in the Zod schema `errorCodeSchema` (ACC-008). The test has JDK 21, Node, pnpm and the network as necessary. The details of the options are in `backend/README.md` and in `frontend/README.md`.

## API documentation

`just api-docs` makes the HTML documentation of the interface from this file. The recipe uses the generator `html2` of the pinned plug-in (the second execution `api-docs` of `openapi-generator-maven-plugin`, no new tool). The output is `build/api-docs/index.html`. The output is not in git. The gate for generated code does not examine the output. Two starts give the same file (REQ-015). The CI job `api-docs` keeps the HTML as the artifact `api-docs`. Note: the page has a font from `fonts.googleapis.com`. A browser makes a network request when it shows the page.

## The recipe `lint`

```bash
just lint
```

The recipe installs Spectral from the lock file in `tools/spectral/`. The recipe examines `contracts/openapi.yaml` with the rules in `tools/lint/ruleset.yaml` (see `tools/lint/README.md`). The recipe must give exit code 0. A warning is a failure too.

## The rules that this file must obey

- **Problem Details (REQ-006).** Each response with a status 4xx or 5xx (also `4XX`, `5XX` and `default`) has the rule of Problem Details. The response uses `#/components/responses/ProblemResponse`, or it has one media type, `application/problem+json`, with the schema `#/components/schemas/Problem`. The schema `Problem` is RFC 9457 (Problem Details). It has the members `code` and `traceId`. The two members are required. `traceId` is the trace identifier of OpenTelemetry (DEC e3eadec0-a6ea-4efe-8e6d-fd19287122fa). `code` is a `$ref` to the one list `ErrorCode`. `ErrorCode` is a string enum. The values are in lower snake case, and no two values are the same (for example `not_found`). The schema has no text that the client shows to a user, in a language (DEC 51b00b5f-d1d8-49d8-9f40-28537ff69698). The backend sends the code, and the frontend shows the text for the code. The members `title` and `detail` have English text for the log and the developer. The client must not show this text to a user.
- **`x-specmgr-req` (REQ-008).** Each operation has the extension `x-specmgr-req`. The value is the identifier (a UUID) of the REQ document of the operation, in `docs/req/`. Make the REQ first (SOP 95b6735b-03b8-47a0-92aa-7934a4ff1519). The operation `GET /status` has the identifier of the REQ "The System Gives Its Status". The recipe `lint` stops an operation with no value or with a value that is not a UUID. GitHub issue #8 has the check that the UUID is the identifier of a REQ document in `docs/req/` (DEC f21920d2-4da5-4cf7-bd94-2e9bcba77342).
- **Version.** `info.version` is the version of the interface (Semantic Versioning 2.0.0).

Do not add a `package.json` in this folder. The SBOM gate (`just sbom`) stops for a manifest in `contracts/`.
