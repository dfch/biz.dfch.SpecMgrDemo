# frontend

The TypeScript frontend. It uses pnpm workspaces (DEC 870244cf-9bea-46bf-8ff2-fe030325743d). The decision for React or Angular is not made (feat-1-frontend-technology-decision), so this module has no component of a user interface.

This folder has the pnpm module and no product code. It has the Zod schemas and the TypeScript types that Kubb makes from `contracts/openapi.yaml` (feat-6-contracts-openapi-pipeline, Phase 120). The first product code comes with the walking skeleton.

| Path | Content |
|---|---|
| `package.json` | The module `frontend`. `zod` is a dependency. `kubb`, `@kubb/core`, `@kubb/plugin-zod`, `@kubb/plugin-ts` and `typescript` are dev dependencies. Each version is exact (no `^` and no `~`), and `just check-pins` compares them with the keys `KUBB_*`, `ZOD_*` and `TYPESCRIPT_*` of `tools/versions.env`. The file has no `packageManager` field (pnpm 12.16.1 is pinned by `PNPM_VERSION`, and the release has no corepack) |
| `pnpm-workspace.yaml` | `packages: ["."]` and nothing else. The SBOM gate scans a pnpm module below `frontend/` only if this file and the lock file exist |
| `pnpm-lock.yaml` | The lock file. It has an integrity value for each of the 102 packages. Install with `pnpm install --frozen-lockfile --ignore-scripts` |
| `kubb.config.mjs` | The configuration of Kubb: the input `../contracts/openapi.yaml`, the output `src/generated` (Kubb deletes the folder first), the plugins `@kubb/plugin-ts` (folder `types`) and `@kubb/plugin-zod` (folder `zod`), and no barrel file, so each generated file has the banner |
| `generate.mjs` | The runner of Kubb. It uses `createKubb` of `@kubb/core` (that is why `@kubb/core` is a direct dependency), and not the command `kubb generate`: the command makes one network call at each start, and `createKubb` makes none. `just generate` starts it and sets `KUBB_DISABLE_TELEMETRY=1` and `DO_NOT_TRACK=1` |
| `tsconfig.json` | The compiler options for `pnpm exec tsc --noEmit --strict` (`just compile`): `moduleResolution` `Bundler` (Kubb writes imports with no file extension) and `lib` `DOM` (Zod uses the type `URL`) |
| `src/generated/` | The generated code. It is committed to git, and nobody changes it by hand: the folder has a `README.md` with the mark "generated, do not change", and each `.ts` file starts with the banner "Generated by Kubb (https://kubb.dev/). Do not edit manually." The gate for generated code (phase 130) stops a change by hand |

The folder `node_modules/` (the install) is not in git.

## Generate and compile

```bash
just generate   # makes frontend/src/generated and backend/src/generated again
just compile    # ./mvnw compile and pnpm exec tsc --noEmit --strict
```

Two runs of `just generate` one after the other make the same files: the files have no time, no version of Kubb and no path of the machine (REQ-011, ACC-013). The schema of the list of error codes is the export `errorCodeSchema` of `src/generated/zod/errorCodeSchema.ts`. `just test-generate-gate` compares its `.options` with the list in the OpenAPI file and with the Java enum (ACC-008).

## Change a version of Kubb, Zod or TypeScript

The version and the integrity value of each package are in three places: `tools/versions.env` (the source), `package.json` and `pnpm-lock.yaml`. `just check-pins` stops if one place is not the same as the others.

1. Look at the license of the new version and of its new dependencies first (DEC 84c37f7d-08cb-457d-8ab3-1db37dba9bc9). The SBOM gate (`just license-check`) checks the tree again.
2. Change the version in `package.json` (an exact version). Run `pnpm install --ignore-scripts` in this folder to make the new lock file with the pinned pnpm.
3. Copy the integrity values from the lock file (the entry in `packages`) to `tools/versions.env`, and compare them with `npm view <package>@<version> dist.integrity`. `kubb` and `@kubb/core` have the version `KUBB_VERSION`.
4. Run `just generate`, `just compile`, `just test-generate-gate`, `just check-pins`, `just sbom` and `just license-check`, and commit the changed generated code with the change.
5. The packages `kubb`, `@kubb/plugin-zod` and `@kubb/plugin-ts` must work together: the versions in `versions.env` are the tested ones.

Do not add a `.npmrc`, a `.pnpmfile.cjs`, `overrides`, a `pnpm` key or a `packageManager` field: `just check-pins` stops for them.
